# Add ads + Remote Config to an existing Flutter app

`/app-factory:build-app` puts this pattern into every new app by itself. This command is for an app that is already built, or was built without ads. Do the steps in order. The rules — where each ad goes, the wiring, the Remote Config keys, Premium, the tests — are in `${CLAUDE_PLUGIN_ROOT}/skills/flutter-ads/SKILL.md`: read it in full before step 2. The installed files are never rewritten; the app only calls their API. This command adds ads and nothing else: a bug found on the way is reported, not fixed. Everything the app already does must keep working: the backend (`lib/data/`, `lib/domain/`) only gains the calls flutter-ads section 7 allows, no existing test is changed, and every test that passed before still passes — step 9's checks I1–I5 prove it from git and the test results, and P1–P18 prove the ads follow the common_flow_demo pattern.

## 1. Check the folder and the device — stop at the first failure and say why

- `pubspec.yaml` with `flutter:` and an `android/` or `ios/` folder. Otherwise: "Not a Flutter app."
- A git repository with nothing uncommitted (`git status --short` prints nothing). Uncommitted changes → stop: "Commit or stash your changes first, so this change is one commit you can revert." No git repository → say the change cannot be reverted with git and that no `ADS_CHANGES.md` (step 9) can be made, and ask whether to go on. Record `git rev-parse --short HEAD` now: it is `<base>` in step 9.
- The app's tests as they are, before anything changes: `"<flutter>" test -j 4 -r failures-only --file-reporter json:.dart_tool/ads_tests_before.json`. Quote the result line. A test that fails here already failed before the ads work: report it, do not fix it (step 9's check I3 counts only the tests that passed here).
- CONTRACT.md section 9 quotes a PRD line saying the app has no ads → tell the user and go on only if they confirm. A PRD line that allows only some formats (Live Street View's PRD 4.9: "interstitial only; no banners, no app-open ads, no native ads") → step 3 places only the rows of those formats and lists every other row as "not placed: PRD <section>", unless the user tells you to place the full pattern; then CONTRACT.md section 9 says so ("full pattern placed over PRD <section> on <date>, the user's choice").
- `lib/google_ads_material/` already there → `diff -r "${CLAUDE_PLUGIN_ROOT}/templates/flutter/ads/lib/google_ads_material" lib/google_ads_material`; list every difference that is not one of flutter-ads section 2's allowed additions (new keys, slots, flags). Do not install again; do steps 2, 3 and 5–10 for what is missing.
- A device with internet, picked without asking anyone: `node "${CLAUDE_PLUGIN_ROOT}/scripts/pipeline.mjs" devices pick android` when the app has `android/`, else `devices pick ios`. Never ask the user which device and never wait for an answer. It returns the first usable connected phone (`"kind":"phone"` — Android woken and, behind a lock screen without a code, swiped open; an iPhone with Developer Mode on), and only when there is none starts the plugin's own device (`"kind":"emulator"` / `"simulator"`); `skipped` names every phone it passed over and why (a code lock, Developer Mode off) — put that line in the report. Use its `serial` / `udid` in every later step. Measured 2026-10-27: the Samsung M04 picked in 0.4 s; with no iPhone connected, `app-factory-iphone-17` started in 61 s. An app launched behind a lock screen never gets focus: `wait-app` then reports not ready.
  **The plugin's own device** (what `devices pick` starts when no phone is usable; `devices up android|ios` alone does the same) — it creates the emulator `af-standard` (or the simulator `app-factory-iphone-17`) when it does not exist, frees memory only by shutting down the plugin's own simulators, starts it in its window, waits until it has booted and settled, and prints `"serial"` (or `"udid"`) — use that id in every later step. Measured on this Mac: created, booted and settled in 132 s; started again in 52–60 s; 0.4 s when it is already running. The whole step 8 passed on it (7 device tests, every placement and exit by hand). It never uses or changes the user's own emulators and simulators. If it fails, its message says what is missing (the system image, Java, memory, disk) — do that, then run it again; there is no other way to get a device. An emulator or simulator has no photos: a picker opens empty, which is enough to check it leaves and returns.
  Android: `pipeline.mjs maestro-install` once (the element list needs it). iOS simulator: `npx -y mobilecli agent install --device <udid>` once per new simulator (mobile-mcp's element list needs it).

## 2. Explore the entire app — before changing anything

Read `${CLAUDE_PLUGIN_ROOT}/skills/app-qa/SKILL.md` rules E2 and E8 first: elements are found and tapped from the element list (Android `read_screen`, iOS mobile-mcp), never by coordinates read off a screenshot; after a launch, `pipeline.mjs wait-app`, never a fixed pause.

**a. From the code — the full list.** Every route, pushed screen, modal, bottom sheet and dialog, each with its file, the screen that opens it and the tap that does. Then: home (the first screen a returning, logged-in user sees); tabs and their roots; the text fields of each screen; a splash screen, onboarding, Premium / paywall screen, store purchase, reward (credits, an unlock); every call that leaves the app — `grep -rnE "Share|share_plus|launchUrl|url_launcher|in_app_review|requestReview|openStoreListing|buyNonConsumable|buyConsumable|restorePurchases|ImagePicker|FilePicker|camera|openAppSettings|mailto:|tel:" lib`. Then the app's own ads and Remote Config code, which the pattern replaces — `grep -rnE "FirebaseRemoteConfig|MobileAds\.instance|(Interstitial|AppOpen|Rewarded|RewardedInterstitial)Ad\.load|BannerAd\(|NativeAd\(|getValue\(" lib --include=*.dart | grep -v google_ads_material` — with every value it reads from its own Remote Config key; the purchase check (where it runs, and whether it runs only inside another fetch) and the rule it uses for Premium; and any connectivity check in front of the startup. Also the app's own ad-tap counter with every line that changes it — `grep -rnE "\b_?(ads?|inter|home|click)[A-Z]?\w*(Flag|Count|Counter)\b" lib | grep -v google_ads_material` (IPTV: `AdsVariable.homeFlag`, bumped in five screens' back handlers) — and the app's privacy / consent row (`grep -rnE "PrivacyOptions|privacyOptions|GDPR" lib`). **The app's own ads layer** — the list passed as `--replaced` in steps 8 and 9: every `lib/` file that imports an ads SDK (`grep -rlE "import 'package:google_mobile_ads/" lib | grep -v google_ads_material`), every `lib/` file that imports one of those to load, gate or show ads (an ads repository, an "ad moment" dialog), every `lib/` file that only they import (ad unit ids, an ads rule), and every test file that imports one of them (`grep -rlE "<file names>" test integration_test`). Live Street View: `data/services/ads_service.dart`, `data/repositories/ads_repository.dart`, `domain/use_cases/ads_rules.dart`, `config/ad_ids.dart`, `ui/features/premium/views/ad_limit_dialog.dart`, their four tests, `integration_test/ads_flow_test.dart` and `test/ui/fakes.dart` (its fake of the repository).

**b. On the device — the app as it is now.** `flutter run -d <id>`, then visit every screen of the list once, in the order taps reach it: from launch, through logging in when the app has accounts (a test account from CONTRACT.md, the seed data or the README; none → register one in the app), every tab, every pushed screen, modal and sheet. Tap a text field and wait 1 s before `input text` (typed earlier, the first letters are lost). On a real phone never pick from the owner's photos or files: a screen behind that is mapped from the code and marked so. On each screen read its element list and record: how you got there, every element that opens another screen and which screen it opens, the text fields, every element that leaves the app. One screenshot per screen. After each screen read the app's log (app-qa section 2); an error there goes in the report.

**c. The app map.** Compare a and b: a screen in the code that the device never reached, or one the device showed that the code list missed, is reached the way the code gives — or listed as "not reached" with the reason. The map has one row per screen: screen | reached from (screen, tap) | taps that open another screen | text field | leaves the app. Stop `flutter run`. Write no file.

## 3. Decide every placement from the pattern

Each row of the map gets its row of flutter-ads section 2 — the pattern decides; do not ask the user which taps count or which banner type:
- each tap of the map is classified by the rows of flutter-ads section 2, and the classification is written per tap: **interstitial** only on a Home feature button, on the action after a feature's picker or sheet that opens its screen, and on a content tab item's main action; **no ad** on switching tabs (bottom bar, a button that switches tab, `TabBar` tabs), a recent / history item, premium, settings, credits, sheets, dialogs, pickers, toggles, secondary item actions, help, and every tap inside an inner screen; each interstitial tap goes through `AdTapHelper.onHomeTap(() => <push>)` with the push returning the route's Future (`Get.to`, `Navigator.push`, `context.push`);
- the Home tab gets one small native below its feature buttons (`NativeAdManager.home`, kept across tab switches);
- the adaptive banner goes on a screen pushed from home or a tab without a text field and not a media player, and on a content tab root; no banner on Home, a collection-management tab, help or Settings tabs, a text-field screen or a player;
- every "leaves the app" entry gets `AppResumeAdListener.skipNextResume()` right before its call;
- splash, intro (big native + intro-finish app open ad) and rewarded rows only when the map has that screen or reward; a Premium screen gets no ad, also not on closing it.

Write the table: screen | ad | trigger / position | Remote Config keys | code | why this row.

## 4. Install

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/ads-install.mjs" "$(pwd)" --no-premium && "<flutter>" pub get
```

If it prints `NOT DONE`, add exactly the lines it prints and run it again. `--no-premium`: an existing app keeps its own purchase code (step 5), so the installer adds no second store setup (`lib/premium_core/` is for apps `/app-factory:build-app` makes).

## 5. Wire

As flutter-ads section 3 says, including its "App shapes" list (no splash screen, `go_router`, no onboarding, no paid tier, tabs). The Remote Config key is `<pubspec name>_v1`. Every placement exactly as the table of step 3; `skipNextResume()` before every call in the map's "leaves the app" column; `block()`/`unblock()` on every Premium screen; `SplashAds.run(isFirstTime: …, homeFollows: …)` (`homeFollows` = Home opens right after the splash); on an intro, `AppOpenAdManager.intro.preload()` in `initState` and `.show(onDone: …, preloadAfter: false)` at its finish; no ad on closing a Premium screen. Code under `lib/data/` and `lib/domain/` imports only `ad_flags.dart`, `ads_id.dart` and `app_open_ad_manager.dart` (flutter-ads section 7). Also, as flutter-ads section 3 says (checks P10–P15 in step 9):
- the crash-report step 1b right after `RemoteConfigLoader.load`, inside `if (RemoteConfigState.firebaseReady)`;
- the startup on every launch, online or offline — a connectivity check in front of it (step 2a) is moved behind it, never around it;
- the app's own ads and Remote Config code of step 2a is replaced: its ad loads, SDK start and Remote Config fetch leave the startup and the screens; the files of its ads layer (step 2a) are deleted, and its tests with them — a test file that also tests other things keeps those tests and changes only what faked the old layer (Live Street View's `settings_test.dart` GDPR test: it counts the UMP channel's `showPrivacyOptionsForm` calls instead of the old fake's counter); each value it read from its own key goes into `assets/remote_config_default.json` with the same value and is read with `AdsId.get(key, default)`; the purchase check that ran inside that fetch runs on its own as startup step 3, unchanged. Report every moved key: the owner publishes it under `<pubspec name>_v1` before release;
- an ads package the app already had at another version is set to the tested version (flutter-ads section 1), then `"<flutter>" pub get`;
- the old ad-tap counter of step 2a and every line that changes it are deleted, back handlers included (a `PopScope` that only bumped it goes, its child stays): `AdFlags.homeFlag` and `AdTapHelper`'s return rule replace them (P18);
- a privacy options entry: Settings (or the app's menu when it has no Settings) shows a row only when `AdsConsent.isPrivacyOptionsRequired` is true, its tap calling `AdsConsent.showPrivacyOptions` (guide app `setting_screen.dart:15,50`); a row the app already has on its old consent code is pointed at these two, never commented out (P17; IPTV `setting_screen.dart:127-141`);
- the intro's own content fits above the 310 dp big native on every page and every phone: no text drawn over the dots, the button or the native and none cut off. Two shapes pass: the screen is a `Column` — the picture part `Expanded` and only the picture shrinks (an image with `BoxFit.contain`, or the illustration alone in `FittedBox(fit: BoxFit.scaleDown)`), the text, dots and Continue at their own size below it, then the native — never the whole page with its text in a `FittedBox` (on a 360×640 phone it drew the guide app's text at 0.47×: a 15 sp subtitle as 7 dp) ; or the design's full-bleed art (`Stack` + `Positioned.fill` image) with the page's text in a `SafeArea` scroll view that ends above the bottom bar, where the dots, the button and the native sit (`Scaffold.bottomNavigationBar` with `extendBody: true`: the body's bottom inset is the bar's height, so the text moves up as the native comes) — Live Street View's onboarding (device, 2026-10-27: 3 pages × 360×640 / 800 dp × font 1.0 / 1.3, title, subtitle, dots, button, native in that order, none overlapping or cut; with the native the text sits higher over the art — say so in the report). Not this: a `Stack` with the image pinned top and the text and button pinned bottom with fixed sizes (IPTV's layout, `intro_screen.dart:58-150`: they overlap on a short screen). IPTV's smaller text while a native can show (`!(AdFlags.isPremium || NativeAdManager.intro.isOff)`, `intro_screen.dart:100,103`) stays. The pinned native gets `minSpaceLeft:` = the height the screen's own content needs, measured on the device at font 1.3 from a uiautomator dump: status bar + top of the page's first text to the bottom of the button + the padding under it (the guide app's intro: 314; Live Street View: 24 + 242 + 16 = 282 — the 330 worked out from type sizes hid the ad on a 360×640 phone where it fits), so it is left out where they would not fit (phone landscape); a native inside a scrolling list gets none. Step 8 checks it on a small screen, a large font and landscape;
- the home native's card (`frame:`) has padding between its border and the ad, the same as the app's other cards (IPTV `stream_now_iptv_screen.dart:100`, `EdgeInsets.all(30.w)` inside a 1.5 px border): the ad paints its own background, so with no padding it covers the border.

- Section 3: a `### ads` group with one criterion per placement, numbered after the highest existing AC.

## 7. Tests

The installed `test/google_ads_material/` and `integration_test/ads_device_test.dart` stay as they are. Per criterion one widget or unit test whose name starts with its id ("AC47 …") and checks the wiring in the app's own screens, with the SDK not started (`AdFlags.adsReady` false, so no platform call):
- the ad widget is on its screen and absent on the screens the table excludes;
- a home feature tap increases `AdFlags.homeFlag` and still navigates at once when no ad is ready; an inner action resets it to 0;
- home sets `AppResumeAdListener.enabled`;
- each call that leaves the app sets the skip window: `AppResumeAdListener.shouldShowOnForeground()` is false right after it (mock the plugin's method channel);
- with a paid tier: Premium shows no ad widget anywhere;
- the launch step, in `integration_test/`, as flutter-ads section 6 says (the splash ad switched off for the run, its loading checked on its own).

## 9. Record what changed, then commit

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/ads-install.mjs" changes "$(pwd)" <base> --replaced <the same list as step 8>
```

`--replaced`: each file is proved from `<base>` — it imports an ads SDK or another listed file, or (`lib/`) only listed files import it; a file that cannot be proved fails I1 with the reason. Proved files are left out of I1, I2 and I4, and their tests out of I3's "no longer runs" (a test that still runs must still pass); the report lists them under "Replaced: the app's own ads layer".

It writes `ADS_CHANGES.md` in the app from git (every file added, changed or deleted since `<base>`, committed or not, with its diff), the template (each installed file checked byte for byte against it) and the code (every line of the app's own `lib/` that uses the ads layer, as file:line), and prints its summary lines. Never edit it by hand and never write it yourself — rerun the command after any later change. A template file marked **differs from the template** whose diff is not one of flutter-ads section 2's allowed additions (new keys, slots, flags) is a mistake: restore it and run the command again.

Its **Checks** section, near the top, is each rule checked by the command, PASS or FAIL with the file:line lines behind it; the command exits 1 when one fails. I = the app as it was still works: I1 only files the ads work owns were touched; I2 no test that existed before was changed or deleted; I3 every test that passed in step 1 passes in step 8 (from the two `.dart_tool/ads_tests_*.json` files); I4 the backend keeps every line it had and gains only imports of `ad_flags.dart` / `ads_id.dart` / `app_open_ad_manager.dart` and `skipNextResume()` / `AdFlags.isPremium = …` / `AdsId.disableAllAds()`; I5 `pubspec.yaml` keeps every line (no existing package or version changed). P = the common_flow_demo pattern: P1 the installed files are the template's (the plugin's selftest checks the template against common_flow_demo itself), only the allowed additions; P2 startup order `RemoteConfigLoader.load('<pubspec name>_v1')` → `FacebookInit.init()` → `SplashAds.run(` → `SplashAds.afterSplash()` in one file; P3 `AppHud.navigatorKey`; P4 `AppResumeAdListener.enabled = true`; P5 `AdTapHelper.onHomeTap(`; P6 `skipNextResume()` within the 3 lines before every call that leaves the app; P7 no banner on a screen with a text field (a search field does not count: IPTV's Channels tab has one and the banner); P9 every `block()` has its `unblock()`; P10 crash reports set as the guide app's `firebase.dart`, behind `RemoteConfigState.firebaseReady`; P11 one Remote Config key, and no Remote Config fetch, ads SDK start or ad load outside `lib/google_ads_material/`; P12 no `if` on the connection before `RemoteConfigLoader.load` in its file; P13 Premium from the store's active entitlement, never a match on product or subscription id names; P14 the ads packages resolve (`pubspec.lock`) to the tested versions; P15 the native settings: `INTERNET`, `AD_ID`, the AdMob `APPLICATION_ID`, `GADApplicationIdentifier`, `NSUserTrackingUsageDescription`; P16 no `AdTapHelper.onHomeTap(` in a tab bar or tab change handler; P17 a privacy options entry on `AdsConsent.isPrivacyOptionsRequired` / `AdsConsent.showPrivacyOptions`; P18 no `++` / `+=` on an old ad counter (`homeFlag`, `adCount`, `interCount`, `clickCount`, …) outside `AdFlags`. Every check must PASS before the commit. A FAIL is fixed in the wiring (never by changing the backend, an existing test or an installed file, and never by editing the report), then steps 8.1–8.2 and this command run again. A FAIL that cannot pass without breaking the pattern — for example a backend line that must change shape to take `skipNextResume()`, or a P13 Premium rule in the app's own purchase code (changing how the app decides who paid is not ads work) — is not committed: stop and show the user that FAIL with its evidence lines.

In an app-factory project: `git add -A && git -c user.name=app-factory -c user.email=app-factory@localhost commit -q -m "app-factory: ads"` — local only, never push. Elsewhere: leave the change uncommitted and list the files.

## 10. Report to the user, in this order
