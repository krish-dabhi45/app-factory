# Flutter ads + Remote Config — the common-flow pattern

One pattern for every app. Its code is `templates/flutter/ads/` — a copy of the guide app `/Users/mach/testing/common_flow_demo` (`lib/google_ads_material/`, its tests, the Android and iOS native-ad factories, `assets/remote_config_default.json`). `scripts/ads-install.mjs` puts it into an app; this file says where each ad goes, how it is wired, which Remote Config key controls it, and how it is tested. The pattern is **not** re-derived per app and its files are **not** rewritten: an app only calls their API.

## 1. Verified facts

**Google's demo ad unit IDs** — used automatically in every debug build (`AdsId.useTestIds = kDebugMode`), per platform ([Android](https://developers.google.com/admob/android/test-ads), [iOS](https://developers.google.com/admob/ios/test-ads), fetched 2026-10-20):

| Format | Android | iOS |
|---|---|---|
| App open | `ca-app-pub-3940256099942544/9257395921` | `ca-app-pub-3940256099942544/5575463023` |
| Adaptive banner (also used for collapsible — Google's table has no separate collapsible id) | `ca-app-pub-3940256099942544/9214589741` | `ca-app-pub-3940256099942544/2435281174` |
| Interstitial | `ca-app-pub-3940256099942544/1033173712` | `ca-app-pub-3940256099942544/4411468910` |
| Rewarded | `ca-app-pub-3940256099942544/5224354917` | `ca-app-pub-3940256099942544/1712485313` |
| Native | `ca-app-pub-3940256099942544/2247696110` | `ca-app-pub-3940256099942544/3986624511` |

A release build never serves an id that starts with `ca-app-pub-3940256099942544` (it counts as `"11"`), so the defaults JSON can hold Google's ids until the owner's real ones are added. Sample **App IDs** (written by the installer, replaced by the owner before release): Android `ca-app-pub-3940256099942544~3347511713` (`AndroidManifest.xml` meta-data `com.google.android.gms.ads.APPLICATION_ID`), iOS `ca-app-pub-3940256099942544~1458002511` (`Info.plist` `GADApplicationIdentifier`).

**Build facts found while testing (each one broke a build):**
- `flutter_svprogresshud` (latest 1.1.0, 2024-11-05) calls `jcenter()` in its `build.gradle`; Gradle 9 removed it → Android build fails. The template's loader is `AppHud` (an `OverlayEntry`, no package). Never add svprogresshud.
- `google_mobile_ads`' `Package.swift` declares iOS 13; `webview_flutter_wkwebview` 3.27.1 (2026-10-19) declared iOS 15 → Swift Package Manager: "requires minimum platform version 15.0"; 3.27.2 (2026-10-20) declares iOS 13 again. The installer pins the tested version under `dependency_overrides:` (`webview_flutter_wkwebview: 3.27.2`, with the guide app's comment) — exact, so a later release that raises the minimum again is never picked up by itself; not under `dependencies:`, where `pipeline.mjs deps` would call it unused and the optimise step would remove it — and sets the iOS deployment target to 15.0.
- `firebase_core` 5.0.0 resolves a firebase-ios-sdk whose `Package.swift` stops with "Firebase requires Swift 6.2.3 or higher. Please upgrade to Xcode 26.2 or later." → an iOS build of an app with this pattern needs **Xcode 26.2+**. (2026-10-21, Xcode 27.0: the full app with this pattern builds for the iOS simulator and passes its device tests — see the Tested line.)
- Facebook is initialised on Android only: `MainActivity.kt` handles the `nativeChannel` → `initFacebook` call; iOS has no handler, so `FacebookInit.init()` logs the `MissingPluginException` and goes on (no crash). An app that needs Facebook on iOS adds the Facebook iOS SDK and a handler in `AppDelegate.swift` — not part of this pattern yet.
- A device test on a locked phone hangs (no frames behind the keyguard): wake and unlock before `flutter test -d <phone>`.
- **iOS, first launch of a fresh install:** with the guide app's `NSUserTrackingUsageDescription` in `Info.plist`, Google's consent SDK shows its tracking explainer ("Our app wants to stay free for you … Tap "Allow" on the next screen", button **Continue**) and then iOS's tracking prompt (**Allow**); `AdsConsent.init` — so the startup — waits until both are answered. Without that key neither shows. A device test therefore needs a person, or the element list, to tap Continue, then Allow; each `flutter test` file installs the app fresh, so they come once per file (seen 2026-10-23 on the iPhone 17 simulator, iOS 26.1: unanswered, the launch test waited until the run was stopped).
- **Package versions are exact, not ranges** — the ones the guide app was tested with (its `pubspec.lock`): `google_mobile_ads` 9.2.0, `firebase_core` 5.0.0, `firebase_remote_config` 7.0.0, `firebase_analytics` 13.0.0, `firebase_crashlytics` 6.0.0, `shimmer` 4.0.0, and with the Premium layer `purchases_flutter` 10.16.0, `shared_preferences` 2.5.6 (`ads-install.mjs` writes them; its selftest compares them, and the `webview_flutter_wkwebview` override, with the guide app's lock file and `pubspec.yaml`). A range resolves the newest release, which nobody has tested: an app found 2026-10-23 had `google_mobile_ads` 9.2.0 before it was tested, and Firebase packages one major version behind (`firebase_core` 4.15.0). An app that already has one of these packages at another version is set to the tested one — `ads-install.mjs` changes that line (its comment kept) and replaces an older `webview_flutter_wkwebview` override; a git/path entry is left as it is and named in its to-do list. Moving to a newer version = the guide app first (its tests on both platforms), then the pins.

## 2. Where each ad goes — the "Ads" section of CONTRACT.md

The placements, timings and Remote Config key names are the IPTV app's (`/Users/mach/testing/IPTV_two`, its `config.json`; section 8 has the file:line for each rule). Map every screen of the app to one row of this table. A screen that matches no row gets no ad. The table decides every placement — nobody is asked which taps count or which banner type. Every placement becomes one criterion: "AC<n> <screen> shows <format> at <position> for non-Premium users; Premium users see none".

| Screen (in this app) | Ad | When / position | Remote Config keys | Code |
|---|---|---|---|---|
| Splash (every launch, first and later) | App open when `appOpenSplash` is not `"11"`, otherwise interstitial `interSplash` | Once per launch, after Remote Config + store check + consent. While it loads, the intro native (first launch) and the home native preload. Waits at most `splashAdWaitSeconds`, then goes on without an ad; the next screen opens when the ad is closed | `appOpenSplash`, `interSplash`, `splashAdWaitSeconds` | `SplashAds.run(isFirstTime:, isReturning:)` |
| Intro / onboarding | One **big** native (media) at the bottom of every page, outside the `PageView`, height 300, shimmer while loading | Shown on the **first launch only**, until the user finishes it (Continue on the last page, or Skip); the "seen" mark is saved at the finish, so an app killed on the intro shows it again next launch; `showIntro` `"0"` = never shown. No timer: the user pages through it. Native preloaded during splash | `nativeIntroBig`, gate `adShowIntroFlag`, native colour keys | `NativeAdWidget(slot: NativeAdManager.intro, height: 300)` |
| Intro finish (Continue on the last page, or Skip) | App open `appOpenIntro` when not `"11"`, otherwise interstitial `interIntro` | Preloaded when the intro opens; at the finish shown only if already loaded (no wait, no loader), and the next screen (rating / premium / home) opens when it is closed | `appOpenIntro`, `interIntro` | `IntroPremiumAds.intro.preload()` in `initState`; `IntroPremiumAds.intro.show(onDone: <finish>)` |
| Rating, Settings, Privacy, Terms, dialogs, bottom sheets | none | — | — | — |
| Premium / paywall | none on the screen. A returning launch sets `homeFlag = 1` after the splash ad step, so the first tap after the splash ad is free. | Inner screen with a text field; a media player screen (its main content plays video / a stream); tab roots | no banner | — | — | — |
| App back from background | App open `appOpenAds` | Every return to the foreground, only after home was reached once. Loaded at start, after each show, and when the app goes to the background without a loaded ad; an ad older than 4 h is reloaded. Not after share / review / store page / purchase sheet / picker / ad click; not while a Premium screen is open; not over another full-screen ad | `appOpenAds` (`"11"` = off) | `AppResumeAdListener` (section 3) |
| A reward the PRD offers (credits, an unlock for a while) | Rewarded | Button the user taps; `onReward` only when earned | `rewarded` | `RewardedAdManager.show(onReward: …)` |
| Premium user | none anywhere, nothing loaded | — | every ad key → `"11"` | section 5 |

**A new placement** (a screen group the table has no row for) follows the same naming, so Remote Config stays readable and app-specific keys can be added later without code changes inside the template:
- An ad key is `<format><Place>` in camelCase — `appOpen<Place>`, `inter<Place>`, `native<Place>`, `banner<Place>`, `rewarded<Place>` (e.g. `interPlayer`, `nativeChannels`). From the prefix alone `AdsId.unit(key)` gives the right Google test id in debug, Premium turns it to `"11"`, and its revenue switch is `sendRevenueToAnalyticsFor<Key>`. A key ending in `Color` is never an ad key.
- A slot: `InterstitialSlot('inter<Place>')`, `AppOpenSlot('appOpen<Place>')`, `NativeSlot('native<Place>', factoryId: NativeFactory.small | NativeFactory.big)` in the matching manager; a banner of another id: `banner<Place>` and a `BannerType`.
- A screen switch that turns ids off: an entry in `AdsId.gates` (`'native<Place>': 'adShow<Place>Flag'`). A second tap group with its own counter: `static int <place>Flag = 0;` in `AdFlags` and a copy of `onHomeTap` that uses it, its slot and `<place>FlagOnline`.
- Add every new key to `assets/remote_config_default.json` and to the Remote Config JSON.

These are the only additions an app makes inside `lib/google_ads_material/` (new keys/slots/flags/gates); the existing code stays as installed.

## 3. Install and wire

**Install** — once, in the interface step (or the first group); in an app that is already built, `/app-factory:ads-implementation` does all of this section: `node "<plugin>/scripts/ads-install.mjs" "$(pwd)"`, then `flutter pub get`. It adds `lib/google_ads_material/` (16 files), `test/google_ads_material/` (unit + widget tests), `integration_test/ads_device_test.dart`, `assets/remote_config_default.json`, `lib/premium_core/` (`PremiumStore`, `FreeUseGate`, `PremiumValues` — section 5) with `test/premium_core/`, the packages at the tested versions (section 1, each with its reason, `firebase_crashlytics`, `purchases_flutter` and `shared_preferences` included), the Android factories (`NativeAdStyle.kt`, `LayoutNativeAdFactory.kt`, `res/layout/native_small.xml` and `native_big.xml`, `MainActivity.kt` registration of `smallNative` and `bigNative` + Facebook channel, `facebook-core`, permissions, App ID, Facebook meta-data) and the iOS factories (`TemplateNativeAdFactory` small and big in `AppDelegate.swift`, so no Xcode project edit; `GADApplicationIdentifier`; `NSUserTrackingUsageDescription` with the guide app's text; iOS 15). An app whose CONTRACT.md says it has no paid tier: `ads-install.mjs "$(pwd)" --no-premium` (no `premium_core/`, no purchase package). It never overwrites a file; when `MainActivity.kt` or `AppDelegate.swift` is not Flutter's default it prints `NOT DONE` with the exact lines to add — add them, run it again.

**Set per app:** the Remote Config key name (`<app>_v1`, unique per app; IPTV's is `iptv_n_v1`) passed to `RemoteConfigLoader.load`; Firebase files (`google-services.json`, `GoogleService-Info.plist`) — without them the app runs on the defaults JSON; an app set up with the FlutterFire CLI (`firebase_options.dart`) calls `await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)` before `RemoteConfigLoader.load` (the loader initialises Firebase only when no app exists, `remote_config.dart`); the owner's App IDs and ad unit ids before release; the RevenueCat keys as build skill L12 keys — `ApiKeys.revenuecatAppleKey` / `revenuecatGoogleKey` from `REVENUECAT_APPLE_KEY` / `REVENUECAT_GOOGLE_KEY` (none → demo mode, section 5) — and the entitlement id from CONTRACT.md's Premium lines.

**Wire** (the app's own splash / startup code — a view model in an MVVM app, `AppFlow` in the guide app):

```dart
// MaterialApp(navigatorKey: AppHud.navigatorKey, …)   ← "Showing Ads..." loader needs it
await RemoteConfigLoader.load('<app>_v1');      // 1. defaults JSON, then Remote Config (10 s fetch timeout)
if (RemoteConfigState.firebaseReady) {           // 1b. crash reports — the guide app's firebase.dart; no Firebase files → skipped
  FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;
  PlatformDispatcher.instance.onError = (error, stack) {
    FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
    return true;
  };
}
await FacebookInit.init();                       // 2. Facebook, id/token from Remote Config ("11" = skip)
await PremiumStore.instance.configure(          // 3. the store's purchase check, on its own (section 5);
    appleKey: ApiKeys.revenuecatAppleKey,         //    Premium → AdFlags.isPremium = true; AdsId.disableAllAds();
    googleKey: ApiKeys.revenuecatGoogleKey,
    entitlement: '<entitlement id>');
await SplashAds.run(                             // 4. consent → MobileAds init → intro + home native preload → splash ad
    isFirstTime: isFirstTime && PremiumValues.showIntro,
    isReturning: !isFirstTime);                  //    returning launch: homeFlag = 1 (first home tap after the splash ad is free)
SplashAds.afterSplash();                         // 5. resume listener + home tap interstitial preload
// navigate: first launch → (intro, rating, premium per showIntro / showRateScreen / showPremiumFirstTime) → home;
//           later → (premium per showPremiumAfterSplash) → home
AppResumeAdListener.enabled = true;              // 6. when home is shown
```

Intro (first launch): `IntroPremiumAds.intro.preload()` in `initState`; the big native under the pages; the last page's Continue and Skip both call `IntroPremiumAds.intro.show(onDone: <save "intro seen", then rating / premium / home>)` once (ignore a second tap while it opens). Premium opened from inside the app: `IntroPremiumAds.premium.preload()` in `initState`, close → `IntroPremiumAds.premium.show(onDone: close)`.

App shapes (the guide app has all of these screens; many apps do not):
- **No splash screen:** steps 1–5 run in `main()` after `WidgetsFlutterBinding.ensureInitialized()` and before `runApp` — the native launch screen stays up until Flutter's first frame, so it is the splash. Keep them out of any function the tests call (`buildApp`-style factories), so widget tests never reach the SDK.
- **`MaterialApp.router` (go_router):** the root navigator key is the HUD's — `GoRouter(navigatorKey: AppHud.navigatorKey, …)`; `MaterialApp.router` has no `navigatorKey`. Home taps open with `context.push(…)` (returns the Future the tap rule waits for), not `context.go(…)`.
- **No onboarding:** `SplashAds.run(isFirstTime: false, isReturning: true)` — with no intro there is no first-launch mark, so every launch counts the splash ad as the first home ad (the first home tap after it is free); no intro rows. **No paid tier:** installed with `--no-premium`, step 3 is skipped, `AdFlags.isPremium` stays false, and the Premium rows of section 2 do not apply.
- **Home** is the first screen a returning user lands on (after login when the app has accounts): `AppResumeAdListener.enabled = true` in its `initState`. **Tabs:** the tab bar is "Home — tab switch" (no ad); a tap inside any tab root that opens a screen goes through `AdTapHelper.onHomeTap` (one `homeFlag` for all tabs, as IPTV); the small native is only on the Home tab; a screen pushed from a tab is an inner screen.

Rules the app's code keeps:
- **The startup runs on every launch, online or offline** — never behind a connectivity check. The guide app's `NetworkController` calls `AppFlow.runSplash()` on the first connectivity result whatever it is (`network_controller.dart`); offline it shows `AppHud.show(status: 'No Internet Connection\nPlease check your connection.')` for 5 s and goes on: Remote Config keeps the defaults JSON, and `AdsConsent.init` still starts the SDK when the consent stored on the device allows it, so ads load once the network is back. An app that skips the startup offline has no ads and no resume listener for the whole session. A home tap is never blocked offline (IPTV blocks it with "Please Start Your Internet." — not copied, section 8): with no ad loaded it opens its screen.
- **The purchase check (step 3) runs on its own**, before `SplashAds.run`, on every launch — never inside another fetch's `try` or success path (if that fetch fails, a paying user gets ads).
- **One Remote Config key, `<app>_v1`, and `lib/google_ads_material/` is the only code that fetches Remote Config, starts the ads SDK or loads an ad.** App values (limits, flags, store keys) live in the same JSON (section 4). An app that already has its own ads or Remote Config code: `/app-factory:ads-implementation` lists it and replaces it.
- Before anything that leaves the app on purpose — share sheet, store page or in-app review, purchase or restore, opening a browser, a photo / file picker or the camera, the system Settings (`openAppSettings`), a `mailto:` / `tel:` link — call `AppResumeAdListener.skipNextResume()` (the next return within 5 min shows no app open ad). Banner and native clicks already do it.
- A Premium / paywall screen calls `AppResumeAdListener.block()` in `initState` and `unblock()` in `dispose`.
- Every full-screen ad continues the user's action in `onDone` (navigation goes there, never before the ad).
- Flow flags `showIntro`, `showRateScreen`, `showPremiumFirstTime`, `showPremiumAfterSplash` (`"1"` = show) decide the startup screens; Premium never sees a premium screen. `showIntro` `"0"` goes straight on as if the intro had finished (no intro ad).

## 4. Remote Config

All values are one Firebase Remote Config parameter named `<app>_v1` whose value is the whole JSON (paste `assets/remote_config_default.json` with the real ids). The app reads the bundled defaults first, then merges the online JSON over them (a key missing online keeps its default; invalid JSON keeps the defaults). Minimum fetch interval: 0 in debug, 5 min in release. Every getter reads the merged map at the moment it is used, so a value applies from the next launch. Values may be strings or JSON booleans/numbers, as in IPTV's `config.json` (`"adShowHomeFlag": "1"`, `"sendRevenueToAnalytics": true`, `"useCount": 3`).

| Key | Meaning | Off / default |
|---|---|---|
| `appOpenSplash` / `interSplash` | splash ad (app open wins when set) | `"11"` |
| `appOpenAds` | app open on return from background | `"11"` |
| `interPreLoad` | home / tab tap interstitial | `"11"`; gate `adShowHomeFlag` |
| `nativeHome` | small native on home | `"11"`; gate `adShowHomeFlag` |
| `nativeIntroBig` | big native on the intro | `"11"`; gate `adShowIntroFlag` |
| `appOpenIntro` / `interIntro` | intro finish (app open wins when set) | `"11"` |
| `appOpenPremium` / `interPremium` | closing Premium opened from inside the app (app open wins when set) | `"11"` |
| `banner` / `bannerCollapsible` | inner-screen banner | `"11"` |
| `rewarded` | rewarded | `"11"` |
| `adShowHomeFlag` / `adShowIntroFlag` | `"1"` = home ads (tap interstitial + native) / intro native on | anything else = off; missing = on |
| `homeFlagOnline` | `"0"` = an ad on every home tap; `"1"` = every second tap (with the return rule) | default `"1"` |
| `splashAdWaitSeconds` / `inAppAdWaitSeconds` | longest wait for the splash ad / a tap ad that was not preloaded | 8 / 5 |
| `sendRevenueToAnalytics`, `sendRevenueToAnalyticsFor<Key>` | `ad_impression` to Firebase Analytics, all ads / one ad (`sendRevenueToAnalyticsForInterPreLoad`) | `false` or `"0"` = off; missing = on |
| `facebookId`, `facebookToken` | Facebook SDK (Android) | `"11"` = skip |
| `nativeBGColor`, `headerTextColor`, `bodyTextColor`, `btnTextColor`, `btnBgColor1` → `btnBgColor2` (CTA gradient; equal = solid), `btnGradientAngle` (0, 45, 90, 135, 180, 270), `btnRadius`, `btnAdBgColor` / `btnAdTextColor` (the "Ad" badge) | native look, both factories, Android `NativeAdStyle.kt` and iOS `AppDelegate.swift` | `#RRGGBB`, `RRGGBB` or `AARRGGBB`; invalid → default |
| `showIntro`, `showRateScreen`, `showPremiumFirstTime`, `showPremiumAfterSplash` | startup screens | `"1"` = show |
| `showShareBtn`, `showRateBtn`, `showPrivacyBtn` | settings rows | `"0"` = hidden |
| `show<Plan>Plan` (`showWeeklyPlan`, `showYearlyPlan`, `showMonthlyPlan`, `showLifetimePlan`, …) | a RevenueCat package type on the paywall (`annual` = `Yearly`) | `false` / `"0"` = hidden; missing = shown |
| `premiumShow`, `useCount` | free uses of each paid feature before the paywall | `premiumShow` `"0"` = no limit; `useCount` whole number ≥ 0 |

An id is "on" when it is anything but `"11"` or `""`; in debug every on id is replaced by Google's test id of its format (section 1); in release a Google demo id counts as `"11"`. A flag is "on" when it is `"1"` or `true`. Each ad has one id (IPTV's schema — no second "normal" id). Full-screen ads preload again after they close (the splash, intro and premium-close ads do not: they show once). Every paid event goes to Firebase Analytics as `ad_impression` (value, currency, `ad_placement` = the key, ad unit).

Changing the app from the console, for example: switch an ad off → its id `"11"`; all home ads off → `adShowHomeFlag` `"0"`; an ad on every home tap → `homeFlagOnline` `"0"`; splash app open instead of interstitial → `appOpenSplash` set; intro interstitial instead of app open → `appOpenIntro` `"11"` and `interIntro` set; sell only yearly → `showWeeklyPlan` `false`; a tighter free tier → `useCount` `1`; no paywall from usage → `premiumShow` `"0"`; no intro → `showIntro` `"0"`; hide a settings row → `showShareBtn` / `showRateBtn` / `showPrivacyBtn` `"0"`; a slow network market → raise `splashAdWaitSeconds`. App-specific values (credits, limits) live in the same JSON, in the same camelCase style, and are read with `AdsId.get(key, default)` from the app's own class (the guide app's `RemoteValues`: `freeCredit`, `weekCredit`, …).

## 5. Premium and consent

- **Premium = the store's active entitlement**: RevenueCat `customerInfo.entitlements.all[entitlementKey]?.isActive` (the guide app, `purchase_controller.dart`); with `in_app_purchase`, a verified purchase or a subscription the store reports active. Never a match on product or subscription id names (`activeSubscriptions.toString().contains("week")` — IPTV's `ads_splash_utils.dart:321`): a renamed or new product silently gives a paying user ads.
- On a purchase or restore that makes the user Premium, and on launch when the store says Premium: `AdFlags.isPremium = true; AdsId.disableAllAds();` — every ad key becomes `"11"` (also when Remote Config arrives later), no slot loads or shows, consent and `MobileAds.initialize()` are skipped at launch. Flags, colours and Facebook keys are untouched.
- **The store: `PremiumStore.instance`** (`lib/premium_core/premium_store.dart`, a `ChangeNotifier` — the view model listens, build skill S3). `configure(…)` once at startup (section 3, step 3): RevenueCat with the platform's key, `addCustomerInfoUpdateListener`, then the cached customer info, so Premium also holds offline. An empty key = **demo mode** (build skill L12 "unavailable"): nothing is sold, the paywall says plans are unavailable, and `demoUnlock()` — Premium without a purchase — works only in debug builds (`PremiumStore` ignores it in release, so a release built without the key never gives Premium away); show its button only `if (kDebugMode)`.
- **Paywall** (the screen that calls `loadPlans()`): `loadPlans()` in `initState`; one row per `PremiumStore.instance.plans` (the offering's packages in its order, without the types a `show<Plan>Plan` key hides; all hidden → all shown) with the store's own `storeProduct.title` and `priceString` — never a hard-coded product or price; `buy(package)` → `BuyOutcome.bought` then `AppFlow`-style navigation, `cancelled` → nothing, `failed` → one short message; **Restore** → `restore()` (only from this tap — RevenueCat: restorePurchases "should not be triggered programmatically, since it may cause OS level sign-in prompts"; IPTV calls it on every launch, `ads_splash_utils.dart:314` — not copied); **Terms of Use** and **Privacy Policy** links (App Store guideline 3.1.1 needs a restore mechanism; subscriptions need both links). `scripts/release-check.mjs` C3 and C4 check these.
- **Free uses before the paywall** (IPTV `checkPurchaseNormal`, `utils/app_variable.dart:93`): a paid feature with a free allowance runs through `FreeUseGate.run('<feature>', action: …, openPaywall: …)` (the guide app's Quick Edit): each feature has its own counter; under `useCount` uses the action runs and is counted; at the limit the paywall opens and the action runs only if the user is Premium afterwards; Premium is never counted or limited; `premiumShow` `"0"` = no limit. The decision is the pure `freeUseAllowed(used:, limit:, isPremium:)` (build skill L1). The default `useCount` is in `assets/remote_config_default.json`, from CONTRACT.md's Premium lines.
- **Settings:** Restore Purchase and Terms of Use are always there; Share, Rate and Privacy Policy rows only when `PremiumValues.showShareBtn` / `showRateBtn` / `showPrivacyBtn` (the paywall always links Privacy Policy). A consumable (credits) is `BuyOutcome.bought` with a `ProductCategory.nonSubscription` product: the app adds its credits; it never sets Premium.
- Consent (UMP): `requestConsentInfoUpdate` → `loadAndShowConsentFormIfRequired` → only if `canRequestAds()` is true, `MobileAds.instance.initialize()` and `AdFlags.adsReady = true`. Until then no ad is requested. Settings shows "Privacy options" when `AdsConsent.isPrivacyOptionsRequired`, calling `AdsConsent.showPrivacyOptions()`.

## 7. How the template relates to the build rules

`lib/google_ads_material/**` and `test/google_ads_material/**` are installed files owned by the shared layer. They are exempt from flutter-app S3 (static managers, not constructor injection — every ad call site in the app is one line), L11 (its packages are listed with their reasons by the installer) and `pipeline.mjs colors` (HUD and shimmer colours; native-ad colours come from Remote Config). Screens use only the API above; a deep audit judges the template against this file, not against S3/L11/U rules. S2 (no `material.dart` under `lib/domain/` or `lib/data/`): code there — e.g. the purchase service's Premium hook and `skipNextResume` — may import only `ad_flags.dart`, `ads_id.dart` and `app_open_ad_manager.dart`, which do not import Material; `SplashAds`, the interstitial and every widget are called from view models and views in `lib/ui/`.
